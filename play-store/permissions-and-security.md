# Permissions and security audit

## Android permissions (what the shipped wrapper asks for, and why)
Splitr's Android app is a Trusted Web Activity: a thin shell that opens https://www.splitr.pro full-screen in Chrome. The site itself is the app.

| Permission | Needed? | Why |
|---|---|---|
| `INTERNET` / `ACCESS_NETWORK_STATE` | Yes | The app is the website: all data is loaded over HTTPS |
| `POST_NOTIFICATIONS` (Android 13+) | Yes (asked only when the user turns notifications on) | Expense, payment, reminder and invite alerts (`enableNotifications: true`) |
| `FOREGROUND_SERVICE`, `REQUEST_INSTALL_PACKAGES`, etc. | **No**: confirm none appear in the generated manifest (see `android/RELEASE.md`, "Check the manifest") | |
| Camera, microphone, location, contacts, storage, SMS | **Never requested** | QR joining is done with the phone's own camera app; the app shows QR codes but never scans them itself |

## Browser features the web app uses (and how denial is handled)
- Notifications / push: optional toggle in Settings; if the user denies, the toggle explains how to allow it.
- Service worker + local storage: offline queue and theme; fails safe if blocked.
- `navigator.share` for invite links, with copy-link as the fallback.

## Security audit results (repository inspected 7 Oct 2026)
- **Secrets in Git:** none found (checked tracked files for keys, tokens, private keys, keystores, `.env*`). `.env*`, keystores and build outputs are git-ignored.
- **Debug code:** no `console.log`, no test accounts, no auth bypasses, no staging or localhost URLs in `src/` (the only `localhost` is a URL-parsing helper in `safe-redirect.ts`).
- **HTTPS:** all app URLs are `https://`; the TWA host is `www.splitr.pro` and Digital Asset Links is served at `https://www.splitr.pro/.well-known/assetlinks.json` (HTTP 200, `application/json`). The bare domain redirects, which would break verification, so the app must always use `www.`.
- **Third-party calls:** removed the `ui-avatars.com` placeholder-avatar request (it sent the user's name to a third party); initials are drawn locally now.
- **Authentication:** Supabase Auth (JWT verified server-side on every API route), per-user rate limits, redirect targets validated (`safe-redirect.ts`).
- **Financial integrity:** integer money maths (`calculateSplits`, largest-remainder), per-currency ledgers, account deletion and leaving a group are refused while balances are unsettled (see tests in `src/__tests__/api/account.test.ts`, `members*.test.ts`, `splits*.test.ts`).
- **Exported components in the Android manifest:** generated by Bubblewrap from a fixed template (launcher activity, TWA verification, notification delegation service); verify after each build with `aapt2 dump xmltree` or Android Studio's APK Analyzer.
- **Release signing:** *not* configured in the repo on purpose; see `android/RELEASE.md`.

## What to rotate or watch
- If a *service-role* or *VAPID private* key was ever pasted into a chat, ticket or screenshot, rotate it. None is in the repository.
